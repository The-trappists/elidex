| 2026-11-07 | Patterns count a problem told in other words as the same problem: same place, plus two guards that nothing overrules (contradicting symptom checks; a workaround vs its cure, checked across whole groups), plus similar words, identical checks, or, with `EMBEDDING_MODEL`, cosine similarity ≥ `PATTERNS_SAME_MEANING` (cached vectors, words only if the model fails). Default 0.78, calibrated on `gemini-embedding-001` with `ctx patterns --check-meaning` (13 labelled pairs: same problem ≥ 0.80, look-alikes that reach meaning ≤ 0.69; the old 0.85 missed every paraphrase). Meaning needs the same element or an overlapping scope, never a shared model alone: the first real run grouped RAD-176's unit-specific frost dip with RAD-198's iced dish (0.82). See `docs/patterns.md` | Topic slug only (repeats split under LLM renames); words only (cannot see paraphrases: hashed words do not separate the labelled pairs); embeddings without guards (look-alikes after an SFP swap would merge) | Reuses the team's validated embedding model; guards and the place check keep "a wrong link is worse than none" | maybe-e (with Claude) |
| 2026-11-07 | Patterns: one feature finds **recurring** problems (same workaround 3+ times) and **linked** problems (elements in separate conversations, close in time, sharing a topology neighbour, site or firmware), and writes hypotheses (hidden suspect, fixes that only clear the symptom, a lasting fix stated but not rolled out). Computed as a view in its own module (`mvp/patterns.py`), never returned as a rule; resolved silently by a later stated lasting fix. Workbench "Patterns" page, `ctx patterns`, REST and MCP. | 2026-11-07 | The loop is fully automated: knowledge goes live with no human review, and no specialist is ever asked for a click, a confirmation or a rating. | 2026-11-07 | Linking stays deterministic (`link.py`: exact IDs, aliases, class from type, model and install years, abstain when unsure). LLM agents sit only where the text is ambiguous. A vague scope word ("old") is kept as `Scope.qualifier` and lowers the confidence of the class by x0.8 instead of becoming a precise class | Let an LLM bind entities; embedding similarity for linking | "A wrong link is worse than none": a deterministic linker can be tested and explained, and a model that guesses an element id would spread a rule to the wrong equipment | UnPtitBelge (with Claude) |
| 2026-11-07 | Keep the pipeline (listen, understand, link, store, reconcile) and add three targeted agents: a critic inside understand (second model checks each item against its quote), a reconcile judge after store (supports, contradicts, supersedes, unrelated against neighbours) and a passive outcome loop (the agent's applied action is posted in a thread, the technician's reply updates trust). No full multi-agent orchestrator. Implemented on branch `worktree-loop-v2`, see [plan-loop-v2.md](plan-loop-v2.md) | A full multi-agent orchestrator (for example Google ADK); better prompts only, with no extra agent | The pipeline is small and works; the three agents target the weak spots (over-wide scope, topic-slug reconcile, trust that never changes) while keeping the stages testable and every agent switchable off. An orchestrator would cost most of the 48 h for no visible gain; prompts alone cannot add a second opinion or a feedback signal | UnPtitBelge (with Claude) |
| 2026-11-07 | Field feedback: after acting, the agent's own observations judge whether a rule worked (symptom checks still there = failed; nothing observed = no verdict). See `docs/evaluation.md` §4 | Close the rule on the first failure; ask a human to confirm; no feedback at all | No human step; one failure can have another cause and one node is not proof for a class; on the labels: 6/6 outcomes judged right, 0 false "contested" alarms | maybe-e (with Claude) |
| 2026-11-07 | Retrieval: no weighting and no strict drop.
